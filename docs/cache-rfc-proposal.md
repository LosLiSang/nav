## 2. 现有代码的实际边界

以下结论来自当前源码，不是对线上缓存命中率或 Cloudflare 实际存储状态的推测。

| 层 | 当前实现 | 缺口 |
|---|---|---|
| 页面内存 | `useNavStore.cachedIcons` 保存域名到 Blob URL；`IconRequestPool` 对同域名请求去重并防止失效后的旧请求回填 | 只管当前页面，不能跨 Worker 实例去重 |
| IndexedDB | `db.iconCache` 按域名保存图标 Blob / 失败记录；账号库与匿名库隔离 | 正图标启动时没有 TTL 检查；失败记录启动时最多保留 7 天 |
| 本地图标清理 | `clearAndReloadIcons` 只删除所选域名的本地缓存，然后正常重新获取；跳过手动图标 | 正常请求可能命中服务端或浏览器旧缓存；这不是服务端清除 |
| 浏览器 HTTP | Worker 图标/title 成功响应给出 `public, max-age=2592000` | 联合刷新后不能撤回已经发给其他浏览器的响应 |
| Worker 抓取请求 | 普通抓取使用 `cf.cacheTtl=2592000`；`force` 请求使用 `cacheTtl=0` | 未显式管理应用缓存；绕过本次缓存不等于删除旧缓存 |
| Worker 应用缓存 | 没有图标/title 的 D1 表，也没有 `caches.default.put/delete` 管理 | 没有可查询的命中、版本、负缓存、失效状态和容量策略 |
| 页面标题 | 按页面 URL 发起抓取；抓不到时按域名搜索索引，再按域名猜名称；这些结果都返回 200 | 不能把猜测结果当成页面真实标题缓存；不同页面需要不同键 |
| 权限 | `/api/icon`、`/api/title`、`/api/fetch-title` 公开；`force=1` 不鉴权 | 无资源级冷却、账号限流、审计或共享范围授权 |
| SSRF | 标题仅检查 URL 可解析；源站请求 `redirect: follow`；图标拼接域名到多个源 | 没有明确的私网地址、域名解析和逐跳重定向检查 |

核查位置：

- `worker/src/fetchers.ts`：`iconResponse`、`titleResponse`、`fetchWithTimeout`。
- `worker/src/index.ts`：公开 GET 路由、CORS、默认 `Cache-Control: no-store` 中间件。
- `src/lib/utils.ts`：图标候选源、`force` 参数、标题 fallback。
- `src/store/useNavStore.ts`：`loadAutoIcon`、本地失败缓存装载、`clearAndReloadIcons`、`refreshIcon`。
- `src/lib/iconRequestPool.ts`：页面内资源所有权和去重。
- `src/components/IconCacheModal.tsx`：当前仅本地清理的范围选择与反馈。

## 3. 提议确认的首期范围

这里不擅自把“受限单项刷新”升级成“普通用户删除整个公共缓存”。
同样不因实现更容易就删去管理员能力或当前用户批量需求；各尺度必须独立批准。

| 角色 / 状态 | 普通读取 | 单项刷新 / 失效 | 当前用户批量联合操作 | 全量公共缓存清除 |
|---|---|---|---|---|
| 未登录 | 公共图标和公开主页标题 | 不允许 | 不允许 | 不允许 |
| pending / disabled | 与访客相同；不能读取账号私有标题 | 不允许 | 不允许 | 不允许 |
| active user | 公共缓存及本人私有标题 | 本人云端书签引用的单项资源；限流、冷却 | **待批准**；如批准，最多 20 个独立资源/次，逐项报告 | 不允许 |
| active admin | 同普通用户，不因 admin 自动开放他人私有标题 | 同普通用户；另有公共缓存管理操作 | 如批准，同上述上限 | **待批准**；单独 API / UI，强确认、全局冷却、审计 |

建议首期批准：受限单项联合刷新 + 当前用户最多 20 项批量刷新。
全量公共清除单独批准；批准前不添加可执行入口或后台绕过通道。
批准这些开发范围不等于授权在线清除任何现有生产缓存。

“本人书签”由服务端从认证账号的 `user_docs` 解析并核对，
不能相信请求中的 `userId`、域名、书签 ID 或前端是否隐藏了按钮。
书签尚未同步时提示先同步或仅清理本地，不能用客户端自报范围修改共享缓存。

## 4. 缓存归属与键（提案）

- 公共图标：按规范化完整域名缓存，保留子域名，不默认将不同站点合并到父域名。
- 公共标题：只缓存公开主页（无查询参数，路径为 `/`）。
- 其他页面标题：按账号私有缓存；访客可执行无持久化、`no-store` 的单次抓取。
- 不从 URL 是否“看起来普通”推断任意路径没有敏感信息。
- 带用户名/密码的 URL 直接拒绝。认证信息不得转发给源站、搜索回退或第三方图标源。
- title 保留路径和原查询串的顺序/重复项；去掉 fragment；统一 host 大小写与默认端口。
  不排序查询参数，不将 `/a` 和 `/a/` 合并，不删除可能影响内容的参数。
- 密钥形式为 `version + kind + scope + SHA-256(normalizedTarget)`。
  私有 scope 使用服务端会话中的账号 ID。缓存键只存哈希，不在公共表/审计日志记录私有 URL 明文。
- 原 URL 即使不写进日志，也可能在源站请求、边缘基础设施或客户端网络日志出现。
  哈希缓存键不是“所有链路都不留痕”的承诺。
- 用户保存的书签标题、手动图标、导航快照、便签、草稿、TOTP 均不是可再生缓存。

## 5. 存储与状态机（提案）

建议复用现有 D1，新增独立 metadata 表、lease 表、限流/审计表；
不依赖按需新增付费 KV / R2，不修改用户业务表。
图标二进制只允许有界数据；是否直接 BLOB 或单独对象存储，最终依据官方限制与测量决定。
当前建议图标最多 256 KiB、标题最多 2 KiB，超限失败不得覆盖已有好值。

```text
正常读
  校验目标与归属
  fresh success -> 命中
  fresh failure -> 返回失败 + retryAfter（不重复抓取）
  expired / missing
    acquire resource lease
    owner -> 有界、受检抓取 -> 条件提交新版本
    non-owner -> 不发第二次源站请求；短暂等待或返回 pending + retryAfter

重新抓取
  active + owner scope + cooldown
  绕过上游缓存，但不先删除旧值
  成功 -> 原子替换 + version++
  失败 -> 保留旧 success，标记 stale / refresh_failed，报告失败

失效
  授权 + 条件版本更新 -> generation++
  旧 generation 请求即使晚返回，也不能回填
  后续读按新 generation 重建；不称为“删除浏览器缓存”
```

建议默认 TTL：图标成功 7 天、真实 title 成功 24 小时、抓取失败 5 分钟。
失败保留的旧值最多提供 7 天降级，并明确 `stale=true`；不得无限保留/无限重试。
域名猜测或搜索索引猜测单独标记 `source`，不伪装页面抓取成功。

并发 lease 建议 30 秒；失败或崩溃后能过期恢复。使用条件 SQL / 单事务获得 lease，
不同实例不能同时声称自己拥有资源。更新成功值必须同时比较 owner 与 generation。
不能以模块全局 Map 代替跨实例所有权协议。

容量建议：每用户私有 title 最多 1,000 条，公共缓存最多 10,000 条；
后台有界清理过期记录（每次最多 100 条），并对达到容量上限的新增明确反馈。
清理与读取/刷新交错也必须检查 generation，不把旧抓取重新插入已失效代际。
这些数值是可配置默认建议，不是已验证的 Cloudflare 平台上限。

## 6. 三种 API 语义必须分开

| 行为 | 修改已存缓存？ | 返回含义 |
|---|---|---|
| bypass（仅绕过） | 不修改共享条目 | 此次向上游请求，不宣称删除 |
| refresh（重新抓取） | 成功后替换；失败保留旧值 | `refreshed / retained_old / failed / rate_limited` |
| invalidate（使旧代际失效） | 推进 generation，旧值不再作为正常 fresh 命中 | `invalidated`，不等同于已经抓到新资源 |

新管理请求使用 POST，不让公开 GET `force=1` 改写共享缓存。
旧 `force=1` 需要收口：匿名返回明确升级/权限错误；前端所有调用点同步更新。
不能悄悄忽略 force 参数然后向用户声称已经刷新服务端。

建议接口：

- `GET /api/icon?domain=...`：正常公共读取。
- `GET /api/title?url=...`：规范化与隔离后的标题读取。
- `POST /api/cache/refresh`：`bookmarkId`、kind、expectedGeneration；逐项反馈。
- `POST /api/cache/invalidate`：同样校验授权和代际，语义不同。
- 如批量获批：每次最多 20 个服务端核对过的资源，并发抓取最多 3 个。
- 如管理员全量公共清除获批：`POST /api/admin/cache/invalidate-public`；
  需要服务端校验 admin、确认短语、操作 ID、全局代际 CAS，不包括任何用户私有缓存。

刷新建议：每账号每分钟最多 10 个新资源任务；每资源 60 秒冷却；
复用正在执行的 operationId 不重复消耗配额。管理员不能跳过总并发上限。
审计只记录 actor ID、资源 hash、kind、scope、operationId、结果、时间，不记录完整私有 URL。
限流检查与操作创建需要原子性，不能靠先 SELECT 后无条件 INSERT。

## 7. 联合操作的顺序与 UI

保留原来的“仅本地清理”，明确第二级操作是“刷新所选本地及服务端缓存”。

1. 显示实际域名/URL 范围、共享引用影响、所需身份、冷却与操作行为。
2. 用户确认后先向服务器刷新；失败不删除现有本地图标，也不覆盖手动图标/书签标题。
3. 服务器成功后清理该资源的页面内存与 IndexedDB 自动缓存，获取新版本。
4. 新请求使用与 generation 关联的 URL 或 `no-store`，不能重新填入旧的 30 天 HTTP 响应。
5. 本地更新也使用资源所有权检查，迟到的旧请求不得覆盖新值。
6. 分别反馈“服务端刷新成功/失败”“本地更新成功/失败”，支持安全重试失败项。
7. title 更新的是自动抓取缓存，不自动将保存的书签标题改成新抓取标题。

部分成功的重试复用 operationId 或最新 generation，只重试未完成阶段：
不能因为 IndexedDB 写失败就再次打源站，也不能把 HTTP 200 的旧值标为刷新成功。
离线时仍可选择仅本地操作；联合操作提示不可用，而不是后台偷偷降级并宣称成功。

其他浏览器已经持有的旧 HTTP 响应无法保证即时删除。
公共客户端下次读通过短浏览器 TTL + 版本策略收敛，不能承诺全球立即强一致。

## 8. SSRF 与资源保护验收

所有出站 fetch（源站图标/title、redirect、搜索/第三方回退）必须通过统一安全入口：

- 只允许 HTTP(S)；限制端口；拒绝 credentials、localhost、单标签内网域名和 IP 字面量。
- 验证 A/AAAA 解析，不允许私网、回环、链路本地、保留网段、IPv4-mapped IPv6 等旁路。
- `redirect: manual`，每跳重新规范化/验证解析；最多 3 跳；不转发账号认证/私有请求头。
- 完整响应读取有总超时与总字节上限，不只在拿到响应头时清除定时器。
- 根域回退、第三方候选源、可执行 SVG / 错误 HTML 冒充图标，都纳入检查。
- 敏感页面标题不得发送给外部搜索服务“猜标题”，公开回退也必须明确标记 source。

需要特别证明 DNS 检查与实际连接目标之间的安全边界。
“先 DoH 查询，再按域名 fetch”本身不是防 DNS rebinding 的完整证明；
在官方能力与本地/运行时证据确认前不得声称 SSRF 完全解决。
如果平台无法约束实际解析/连接，必须收紧抓取目标或选择有目标 IP 校验能力的抓取层，
不能为了让测试通过而忽略这一限制。

## 9. 实现前先写的 E2E 失败矩阵

沿用标题/图标主流程，不新增每个缓存分支各自独立的 E2E。
使用真实 Worker 本地运行时 + 隔离 D1 + 可计数的上游夹具，不访问生产账号或缓存。
网络夹具不能代替真实缓存模块、路由、权限、数据库状态或前端操作。

| 失败方式 | 必须观察到的端到端证据 |
|---|---|
| 相同资源重复抓取 | 首次 MISS、第二次 HIT、上游计数不再增加 |
| 不同页面共享错误标题 | `/a`、`/b`、重复查询参数分别有不同值/键 |
| fragment、host 大小写造成重复 | 规范化命中同一个条目 |
| 私有 URL 泄露 | A/B 同 URL 不共享私有结果，访客不能读取；日志/公共表不含原 URL |
| TTL 不生效 | 推进夹具时钟/条目过期后仅一次重建，source/版本可观察 |
| 失败抓取风暴 | 负缓存命中 + retryAfter；计数与冷却/配额断言 |
| 刷新失败删除好值 | 网络失败保留旧 success；反馈 retained_old，不能宣称 refreshed |
| 刷新/失效与旧请求竞态 | 延迟旧响应；失效后旧 generation 不提交 |
| 两个 Worker 实例并发 | 同 D1 锁/lease 下只有一个 owner 发起抓取 |
| anonymous/pending/普通用户清空共享缓存 | 后端分别拒绝；数据库行/代际保持不变 |
| 客户端伪造归属 | 修改 userId、bookmarkId、URL 不越权 |
| 本地成功但服务端失败 | 两阶段分别报告；重试只推进失败阶段 |
| 浏览器旧值回填 | 预先缓存旧图标；联合刷新后显示新版本，不被迟到请求覆盖 |
| 业务数据被当成缓存 | 清理前后完整比较书签标题、手动图标、设置、账号配置和待同步数据 |
| 20 项批量上限/管理员范围 | 批量获批后验证 21 项拒绝；管理员操作不涉及私有业务数据 |
| SSRF/重定向/DNS 边界 | 私网/编码 IP/IPv6/公转私重定向拒绝，受保护上游计数为 0 |
| 大响应/慢流/崩溃 lease | 总超时、字节上限、lease 过期恢复且不产生无限重试 |
| 明暗与窄屏 | 真实操作、提示/确认/部分成功截图，前景对比度与无溢出 |

每次输出 JSON 报告、上游请求计数、脱敏缓存/审计摘要、明暗截图与失败重试证据。
先运行看到与缺失功能对应的失败，再写实现。不得以 stub 返回“成功”当作后端完成证据。

## 10. 发布与完成门槛

- 本方案涉及权限、作用域、存储的部分先由用户确认；不把讨论起点当作批准。
- E2E 矩阵中的获批尺度全部落地；没批准的尺度写明不开放，而不是默默删掉需求。
- 前端 build、Worker typecheck、打包 dry-run、原有同步与侧栏回归通过。
- 新增 D1 表/索引只做增量迁移；先保留快照/审计备份，不执行业务数据删除。
- 获得生产发布授权后先迁移，再发布 Worker，最后 merge 前端功能 PR。
- 生产只做必要的非破坏性读取/验证；清除生产缓存需要单独明确授权。
- 验证 PR 确已 merge、必要服务可用、issue 的每项验收有对应证据，才能关闭 #10 / #12。
- #7 需 #9 / #10 / #11 / #12 全部满足才可收尾。文档 PR、dry-run 或本地 stub
  都不能单独证明架构总议题完成。
